## 🔷 1. ✅ Naming Rules

### 🧠 Variables, Functions, State
- Use `camelCase`: `userData`, `taskList`, `handleSubmit`
- Never use `UserData`, `User_Data`, `Userdata`

### 🧱 Models (Mongoose)
- Model Names: `PascalCase` → `User`, `Task`
- File Names: `lowercase.dash.js` → `user.model.js`

### 📦 Components
- File/Component Name: `PascalCase` → `TaskCard.jsx`, `UserProfile.jsx`
- Props/State: `camelCase` → `user`, `task`, `setIsLoading`

---

## 🔷 2. ✅ ID Handling (`_id` vs `id`)

| Layer        | Always Use        | Example              |
|--------------|-------------------|----------------------|
| MongoDB      | `_id`             | `task._id`           |
| Backend API  | Keep `_id` as is  | `res.json({ task })` |
| Frontend     | Access `_id` directly | `task._id`      |

> ⚠️ Do **not rename** `_id` to `id` in just one layer.

---

## 🔷 3. ✅ API Planning Before Writing Logic

**ALWAYS write this first before creating controller/route:**

- Endpoint: `/api/tasks/:id`
- Method: `GET`, `POST`, `PUT`, `DELETE`
- Requires Auth? `Yes / No`
- Request Body:
  ```json
  {
    "title": "Read Book",
    "description": "Read 10 pages"
  }
  ```
- Response Structure:
  ```json
  {
    "success": true,
    "task": {
      "_id": "123abc",
      "title": "Read Book"
    }
  }
  ```

## 🔷 7. ✅ Auth & Token Flow (JWT)

1. Login: `/api/auth/login` → returns `{ token, user }`
2. Save token in localStorage
3. Send token in headers for protected routes
   ```
   Authorization: Bearer <token>
   ```

## 🔷 9. 🧼 Naming Anti-Patterns (🚫 NEVER DO THIS)

| ❌ Wrong           | ✅ Correct          |
|--------------------|---------------------|
| `UserData`         | `user`              |
| `res.data.userData`| `res.data.user`     |
| `taskId` (for DB ID)| `task._id`         |
| `User` (prop name) | `user`              |
| `getdata`          | `fetchUserData()`   |
